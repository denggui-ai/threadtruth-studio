## 3. 模特因子如何交付

沿用现有 `factors` 数据，不扩展schema；内部保留**条件/值、状态、来源**，用户需要查看因子时才展示三列表。状态区分建议目标、已确认固定、允许调整、未知；来源区分用户要求、参考可见、系统建议。默认把一个推荐方向并入方案，备选按需展开；首张内部核对实际表现，用户接受后及时记录。

| 因子 | 用户应知道什么 | 约束 |
|---|---|---|
| 面部、可见年龄感、肤色 | 当前身份参考和允许变化范围 | 年龄感不是精确年龄；不得从图推断国籍/民族 |
| 胖瘦、肩线、身体比例 | 参考可见部分与新提出的视觉目标分别列出 | 脸照不能证明身体；不虚构身高、胸腰胯或真实尺码 |
| 妆发、表情、气质 | 默认沿用什么、用户允许调整什么 | 长期允许调整不等于当前编辑可改；保护区涉及它时必须说明冲突 |
| 目标市场与审美 | 用户提供的市场背景和具体可见审美方向 | 市场/国籍不能简化为脸型，也不能由衣服推断真实客群 |

固定姿势路径属于明确选用的可选功能。它锁住既有姿势和受保护区域；要求换发型、表情、头部角度、身形或穿上与保护边界冲突的高领/帽子时，说明该路径无法直接满足，再让用户选择合适的任务方式。不能静默改身份，也不能把所有新商品都导入此路径。

## 6. 防止再次偏移

开发任务回答“下一步”时内部核对当前交接、具体缺口及结束条件，不默认向用户展示D编号。普通单张任务已接受即结束，不因用户询问下一步自动制造开发、试验或安装工作。

新的证据若不改变决策，就不重复测试；已有用户授权保留其原范围，不重复索取同一批准，也不从历史次数推断新额度。修改排期在本文件更新原因和证据，历史报告保持原样。此文档只约束本模特开发任务，不让普通生图任务承担额外开发审查流程。
