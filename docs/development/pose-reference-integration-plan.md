# 裁光姿势参考层与九张交付改造方案

日期：2026-10-29。状态：draft，方案审阅用；未实施运行时修改、安装或生图。范围：图库全量结构分析、288组代表视图审阅、候选多角度核对，以及现有能力复用设计。

## 结论和边界

建议建设可选姿势参考层，并设计可选9张系列。保留现有6张为兼容默认，效果验证后再决定是否改变默认数量。姿势参考层的价值在于把抽象动作变成可选择、可逐张传入和可比较的视觉依据；这个第三方图库只作为可替换的数据来源，不成为运行时依赖或服饰摄影标准。

两个工作包分开验收：先在现有6张链路接入姿势引用，再扩展9张。这样能区分“图像参考是否改善动作”和“增加张数是否带来信息价值”。本方案不重新建设人物包、风格目录、任务账本、生成器或验收状态机。

审查基线：开发仓库 `590908433326f076be8e514eb142a45fcc24db3b`；当前安装版 `1.0.0-beta.14+codex.20261019T163011-d70d4e10`。第三方源提交 `072a3690af6e7e0011abbe0fa1ccc08939fbb47d`。资源和分析证据在本机工作台 `outputs/pose-reference-analysis-20261029/`，完整克隆位于工作台 `ai-pose-gallery-zh/`；2899个文件均校验Git blob与SHA256，2878张图片全部解码通过。原始素材不进入裁光仓库或发布包。

## 资源全量分析

数据共有1439条、288组姿势、4个体系、26种分类、5种视角；原图和缩略图各1439张。287组有完整五视角，`full_sexy_P018`缺仰视，不能把288×5当作实际文件数。分组键采用来源体系和姿势编号，P001等编号跨体系重复，不可单独作为全局ID。标准系编号不连续，不应补造缺号。

| 体系 | 组数 | 图片数 | 对裁光的处理建议 |
| --- | ---: | ---: | --- |
| 全身单人标准系 | 73 | 365 | 逐项审查身体关系、服装遮挡和适用商品；不是自动通过名单 |
| 上半身单人 | 80 | 400 | 前25组“可爱系”可作为手势候选，其余55组不进入默认检索 |
| 全身单人性感系 | 80 | 399 | 不进入服饰默认检索；其中个别普通动作也不值得为此整类引入 |
| 双人缠绵 | 55 | 275 | 当前单人服饰范围不接入 |

73+25=98组仅是粗筛候选，不能宣称98组已经适合商业服饰或已经获得许可。288组代表视图均按原有分类查看；候选8组另核对五角度共40张缩略图。机械全量校验与视觉审阅分开记录，不能称为1439张原图逐像素艺术验收。

素材为偏女性人体比例的人偶线稿，没有眼神、服装、真实表情或商品结构数据。未提供骨骼关键点、深度、相机参数、3D网格或OpenPose文件；普通PNG不能当成硬姿态控制。五视角标签是观察视角，不是人物头向，更不证明可用的真实人脸角度。部分上半身图边缘有局部辅助线/手部残片，选作输入前要审查，不宜将其当成干净的标准人体模板。

元数据只有名称、分类、视角、文件路径和拼接检索串，缺承重、手位、身体程度、遮挡部位、商品用途和许可范围。前端是关键词筛选，查“叉腰”未命中“双手扶腰”，需要少量人工同义词；不必引入向量数据库。原站下载器按文件存在和大小跳过，校验器主要检查文件头，不能代替哈希与实际图片解码。

仓库README说素材不构成商业授权，LICENSE明确写素材不得用于商业用途；原作者网站的注意事项则允许作品制作的商业使用，禁止素材本身再分发、转载和再售，并对真实人物和未成年人用途另有限制。记录为来源条款不一致，不能把MIT用于图片许可推定。

因此本库本轮是本地研究来源。正式商业使用须针对实际来源和具体使用获得清晰许可；公开插件不打包这些原图、缩略图、加工联系表或整套翻译数据。推荐运行时只带少量自有/明确可分发的姿势卡；用户自带图片通过同一个接口接入。换图源不影响任务结构。真人/童装并非产品功能永久禁用，但这套来源不能自动进入这些分支；相应素材需独立适用许可和内容审查。

## 六张优先接入的具体契约

### 图库是素材来源，shot_plan是唯一逐张方案

本地准备阶段读取外部目录和已选来源；运行前把实际选择的图快照复制进现有任务references目录。生成阶段只读取冻结文件，不在线下载、不依赖外部图库仍可访问。

索引最小信息：来源ID与版本、源文件相对路径和SHA256、中文名称及少量别名、观察视角、已审身体/支撑/手位说明、适用范围、已知遮挡、来源与许可证据。先执行许可/人物类型/商品覆盖/内容适配过滤，再按姿势相容性排序；不凭向量相似度或分类标签自动通过。

在现有v1 shot_plan里新增可选`pose_reference`扩展（无此字段走旧分支，渲染字节保持）：

```json
{
  "pose": 1,
  "master": "SIDE_TURN_STANDING",
  "framing": "full-body",
  "garment_views": ["front-side"],
  "reference_sha256s": ["<商品哈希>"],
  "pose_reference": {
    "asset_id": "<来源命名空间及图片ID>",
    "sha256": "<姿势图片哈希>",
    "source_version": "<来源提交或版本>",
    "use": "body-only",
    "match_note": "<已核对身体关系和差异>"
  }
}
```

示意中的哈希是占位说明，实际校验须为真实64位哈希。新字段不能挤进原`reference_sha256s`：后者目前是商品引用，被商品coverage校验使用。默认每张至多一张姿势参考；多视角帮助选图，不一次把五张都传入。若与经典动作不相容，须按现有adapted及实际用户要求记录修改；不能一面写classic一面传冲突图片。

任务库存新增`pose-reference`角色，固定含义是身体动作/关节与承重参考，不复制人物身份、体型比例、服装、皮肤、线稿风格、景别或背景。摄影视角与姿势图的透视不相容时换图或明确适配，不能靠“忽略机位”承诺消除图像影响。头眼继续在head/gaze或real_face_plan中声明；线稿不新增人脸覆盖。

许可、来源审阅等元数据保存在冻结素材记录中，并纳入references_sha256；slot中只保存选定身份/哈希及本张适配信息，避免复制大块图库记录。若采用引用式许可记录，任务内必须快照其内容与哈希，不能只留易变网页链接。

### 统一实际附件选择

当前AI分支会把所有非商品参考传给每张；仅添加角色会导致六张pose全部进入每次调用。这是本次必须修复的具体出口。

在`web-task.py`内抽取一个纯函数解析本次选中参考，供create预检、preview_candidate、continue-authorize、retry、references/export共用，最后再由现有references函数完成文件验证和首张锚点追加。不要新增第二套参考选择状态机。

- AI/new：当前slot商品引用＋原身份/有效补充＋明确审美图＋当前slot姿势图；后续图再加现有identity-only首张锚点。
- real：沿用real_face_plan中声明的完整实际附件顺序；shot_plan新增姿势哈希必须被该slot选中，且角色一致。只有原identity-reference进入coverage。
- 相同文件多角色不做无差别哈希去重；保留原身份组去重语义。角色歧义按现有真人规则拦截。
- 所有路径在冻结前按最终列表预检。当前5图限制明确是`codex_native`分支的现有策略；网页仍按其实际能力和当前实现处理，不把二者错误宣称同一个硬上限。
- 超限时优先重新选择足够的素材；不得丢掉必要商品/原身份/已确认首张。用户若已指定姿势图，不静默退回文字。可提出文字规划或其他素材组合，但变更显式记录。

`handoff_prompt()`按实际附件序号写“本Shot对应Image N”，序号每次从选中列表计算，不能存死在姿势卡中。`handoff_manifest()`保留已有计划/提示词/参考哈希，并增加本次slot到pose输入的映射；reserve和网页execution封套沿用相同结果。

### 预览与独立图

单张成片传单张姿势原图。六格/九格预览可将当次选定的姿势图按对应slot排成一张本地参考板：每格清楚编号、只包含选定姿势、保持比例、不改动作；它只是一张参考附件，不能替代真实商品和身份来源。

参考板仍用`pose-reference`角色，冻结记录增加`kind=single|board`；board仅被预览选择，单张只选single。原图和板图均保存在任务库存，实际选择不可把两者全传。参考板是从多张输入确定性派生的文件，复用现有冻结/哈希体系保存板图SHA256、各格原图哈希、矩形和渲染版本。未选姿势的格子留清晰空位，不擅自配图。调用前核对映射；正式成片从原始姿势图取对应slot，不能从预览生成结果裁出“姿势真相”。

这能减小附件数，但不保证模型准确读小格：九格尤其需要实测姿势识别。板图仍需许可允许相应处理和本次使用。若来源不适用或板图不可靠，可以保留当前文字预览；必须说明预览未使用像素姿势约束，不能宣称已验证独立图效果。

`prepare-delivery`沿用冻结姿势图、shot_plan和对应版本；不自动把板图继续传给每张成片。预览修改姿势引用时沿用revise-preview的候选→授权重试→历史留存；新增`pose_references`输入扩展，不滥用garment_references。只换已有库存的引用时不复制素材。单张重试只改该slot，保留已接受首张、其余slot、原授权和累计次数。

## 九张方案

### 产品选择

建议新增“9张扩展系列”，初期不替换默认6张。新增三张须各有实际用途：

| 新增位置 | 用户得到什么 | 第一版实现范围 |
| --- | --- | --- |
| 7 | 另一侧/斜侧的轮廓与垂坠展示 | 有源图支持的自然站姿变化；无背面资料不借侧面补造背部 |
| 8 | 上半身的领肩袖和人物互动 | 已有half-body景别，手位不遮挡本次重点 |
| 9 | 面向特定商品的第二个补充展示点 | 例如另一侧腰线、袖身或层次关系，沿用现有half-body/knee-up；无新增信息则不建议9张 |

第一版维持单人服饰同一输出形态，不夹入平铺、纯局部无人物或微距镜头。真正的工艺微距需要独立的近景构图、源图充分性与逐shot可见性契约，不能把现有half-body重命名为微距；作为明确后续范围，不为凑9张塞入首版。

九张允许同一动作家族承担不同展示目标，但仅换背景/裁切而无目标差异不能算有效新增。原六张去重规则继续适用经典六张；扩展三张按已冻结用途、身体关系、手位和可见商品差异验收。若用户明确要求九个不同身体动作，应据此另排，并在不支持时说明，不能把上述“九张展示系列”冒充九个全新动作。

### 数据与兼容

当前`pose=1..6`同时表示成片序号和母版，`MASTERS[n-1]`、`real_face_plan`及visual_plan都依赖固定数量。不能全局把6替换成9。

九张使用`shot_plan.version=2`：`slot`表示1..N位置，`master`表示可复用的现有身体家族，另有`purpose`说明本张展示目标；沿用framing、garment_views、head/gaze和pose_reference。v1保留原校验/渲染；内部用小型访问函数取得slot/master/count，旧冻结任务不自动迁移，不改旧prompt/hash。

visual_plan只做相应版本适配：新版本按slot绑定摄影，身体关系仍来自shot_plan。real_face_plan按本次计划数量校验，但原身份覆盖逻辑不变。任务顶层仍使用现有账本，新增可选series_size声明1/6/9，使“先试首张、准备续8张”的预检能提前算上后续锚点。只支持已声明的1/6/9，不趁机做任意N框架。

classic-6保留原顺序；extended-9的前六张默认继承classic-6，7—9显式安排。单张试图续组按series_size追加5或8张；首张内容和身份确认不得被续组改写。其他编号单张、custom、model-check、correction-edit继续各自分支，不冒充首张续组。

### 额度和预览

当前B7为每次请求最多6次调用；九张需要显式修改该产品规则后才可执行。计划总张数与实际授权调用预算分开：新规则可接受用户一次明确授权9张，首张确认后在余额内续8张，所有重试/未知请求继续计数。不能把旧6次授权自动提升到9次，也不能分两个任务清零或绕过B7。

默认方向预览从2×3扩为可选3×3，成片仍是9张独立图。若需要一次九格方向预览再九张成片，基础成本是1+9=10次，不是9次；方向确认不替代后续成片授权。计划、实际图片计数、同画幅、停止/恢复、QA和用户接受需共同适配。

## 文件级工作包

### A 姿势引用接入

新增一个姿势参考说明与一个本地辅助模块；修改shot_plan可选字段和web-task角色、统一选择、预览/修订/继承/实际导出；必要时小改real_face_plan的跨计划一致性检查。SKILL入口只增加一条按需路由，prompt-build/preview-ledger/commercial-qa各补对应职责，原36执行入口及24风格包不复制动作库。

先用授权清楚的2—3张自有/用户提供参考完成单张与六张的确定性出口测试。第三方整库不进入运行包。完成条件：实际附件与slot绑定正确、旧任务不变、来源不适用与超限能明确处置；这只证明链路，不证明画面改善。

### B 有限实图比较

在另获生图授权后，用固定商品、人物、动作与摄影方案，比较“现有文字”与“文字＋精确姿势图”。选站立回转、轻前倾、自然支撑三个不同问题，每个条件一次，共6次，保留全部结果不挑图。原库P071不符合轻前倾，不可用它测试该目标；缺精确参考就先补合适来源。

评价身体朝向、手位、承重、程度和景别，同时检查商品结构、人物身份和线稿/体型渗入。只得出这三个场景的限定结果；重复采样和更多风格仅在新证据需要时安排。若动作没有改善或其他关键项退化，保留为可选手动工具，不默认开启。

### C 九张系列

A完成后才实施数量扩展；使用v2 slot/master契约，修改web-task固定数量与续生、shot_plan、real_face_plan、visual_plan/visual_library、预览排版、QA、B7与交付说明；不新增独立九张脚本或账本。用一套具有明确新增展示点的商品验证9张，沿用既有首张确认与逐张QA。九张实际调用另获明确预算；静态通过不宣布九张生产可用。

### D 发布

只在上述选定范围验收后打包。使用现有build-release与校验，确认包内没有研究图库、第三方联系表、私人任务和绝对路径。原风格包和身份包格式没有必要不改。安装与公开发布仍属于各自授权动作。
