# 基于现有任务记录的跨组姿势避重（2026-11-02）

状态：`candidate/source`。用户明确授权从`e0b98f5`在既有`feat/pose-library-minimal`分支／worktree继续，开工无未提交改动。范围为明确选定任务之间的确定性姿势比较，不建数据库，不进行新的图像或模型评测。

## 实现与边界

- 新增只读`pose_history.py`，只读取指定的任务JSON；支持查看摘要、对照拟定shot_plan。匹配依据为相同pose_id、冻结快照中相同自有动作组、规范化后完全相同的身体／手位／支撑组合。共享几何来自任务快照，不用当前库反推旧内嵌卡。
- 只统计有返回文件哈希的returned／accepted／rejected项；部分系列不统计未返回格，重试读取当次保留的计划快照，预览注明preview-grid。草稿、未知／失败请求与不支持的旧计划列出跳过原因；无可比较记录返回no-comparable-history，不能宣称避重通过。
- `visual_library.prepare`支持可选`pose_history_tasks`，将来源／计划／返回文件哈希、动作键／文字摘要及状态冻结到`visual_plan.pose_history`。不复制历史图片、提示词、客户原文或路径；无数据库、全目录索引、自动历史回写。
- 未说明理由的匹配在prepare及真实账本创建／导出／局部重试校验中拒绝；确有商品展示价值或用户明确指定时，look可写具体`pose_reuse_reason`。理由记录为复用，不当成“没有重复”，不传入图像提示词，也不改变素材与人物门禁。
- 新完整系列／series-first检查整个系列，standalone只核所选项。预览承接／续图保留同一冻结历史，不自动将本组纳入过去组；导出不重读原历史目录。旧任务不自动增加该字段，经典v1保持原路径。

这是规划记录的比较，不是图像姿势识别。返回、接受或拒收状态均不证明图片真正兑现所规划动作。不同措辞表达同一骨架、无共享出处的旧跨卡等价动作、近似姿势算法与推荐评分仍未实现。调用者需选择与本次用途相关的独立历史组；工具不推断任意任务是否同组，也不扫描全部私人目录寻找它们。
