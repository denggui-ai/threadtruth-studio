# 商业交付 QA 与状态阻断(core,风格无关)

> 本文件定义动作1独立成片的最小商业 QA。它不把 LLM 目测包装成像素测量或平台验收,也不改变 safety-core R1–R7、B7 额度上限或用户付费授权门禁。

首张技术 QA 与用户选人是两道门:技术接受不得自动记为用户喜欢。成人首张接受但未确认人物时不传播;换商品首张再次确认人物与上身效果。只有脸的参考不按原人物真实身形验收,只按明确呈现目标验收。参考卡固定/可调/未知及来源须和实际提示词一致。

固定姿势局部换装另按 `fixed-pose-wardrobe.md` 核验本次母图→输出的头脸像素保护，并检查旧衣料残留、发丝/颈部、肩袖/腰侧、手部与包带合成边界。像素零变化仅证明未新增母图脸部改动，不能关闭原照保真、不同母图之间的连续性或商品结构待核项。有限可用性接受不等于 `image-ready`；确定的结构漂移仍为 `qa-retry`。

## 1. 何时执行

- 每张动作1成片落盘后都执行内部基础 QA。
- 商用、上架或客户交付仍需对应内部逐张/整组检查；面向用户默认展示图片与简短结论、影响使用的问题、实际文件和尺寸。只有用户要求详细核对或故障恢复需要时才展开完整检查表。
- 动作0 contact sheet/preview-grid 不进入商业 QA,也永远不能借 QA 升成片。
- 动作2单张内部复用逐张检查；按单张任务收尾，不附整组报告或为尚未要求的五张制造缺项。

## 2. QA 处置词(不是新的主生命周期状态)

- `qa-pass`:可见硬事实、适用的身份一致性和构图目标未发现阻断漂移。
- `qa-retry`:发现可见硬事实、身份、人体、安全或交付结构失败;对应图片仍是 `image-draft`,必须重试或移出交付组。
- `qa-user-review`:logo/文字、细微面料、隐蔽结构或源图未提供的角度无法可靠确认;不得自动当作通过,须用户/运营与实物或高清源图比对。所有风格的**本轮已声明且可定位的视觉目标偏离**——例如光线方向/塑形/接触阴影/轮廓分离/空间层次未兑现、六张光线不一致，或未被人物条件覆盖的风格气质未兑现——也归本处置词:逐条写明目标、实际表现和偏离理由交人工裁决,不自动判废、不自动通过,也不产生额外调用授权。只评价对应风格与当前任务的目标，不把暖光、深木背景或强对比变成24风格共同标准；普通主观偏好可列效果建议。

同一张可同时有 `qa-user-review` 项和其它已通过项;只要存在一个 `qa-retry`,整张与整组都不得升 `image-ready`。

已能对照源图确认的结构漂移(例如平贴矩形白标被画成圆底口袋、增加垂挂条或重复标记)必须是 `qa-retry`,不能降为“细节待核对”。仅源图不足、遮挡或无法可靠判断时才用 `qa-user-review`。已确认深靛蓝牛仔裤被画成明显偏浅、洗水中蓝也属主色漂移=`qa-retry`，不能仅归因光线而放行；无法可靠对照才列待核对。缺背面时可按 `prompt-build.md §1b` 在生成前明示替代第六张,但不能用改姿势掩盖已经发生的结构漂移,也不能将背部未知标为已核实。

### 按商品用途区分阻断与普通意见

- 颜色、款式、主要结构、身份/人体、安全与实际尺寸等明确硬错误仍为 `qa-retry`，不能因用户满意自动通过。
- **自然遮挡不等于裁切。** 全身开衫人像中，迈步时后鞋自然被前腿遮住，只要没有人体缺失证据、服装主结构仍可评估，不自动判废。若鞋本身是商品主角，或用户明确要求两鞋分别无遮挡，则按该要求检查；不要自行把“全身”升级为“两鞋始终完全无遮挡”。
- 商品以外、未被用户锁定的搭配细节差异（例如均为白闭口鞋但鞋型不同），列为整组待核，不能宣称完全统一；用户明确锁定鞋型或完整outfit来源时仍按硬事实验收。
- 坐姿衣料自然起皱、手臂自然遮挡与商品结构缺失分别判断。若方案明确要求门襟/衣摆完整展示而实际被遮住，按未达到展示要求处理；不能仅凭“坐姿自然”关闭该项。未锁定为逐张必露的细节可以列待核，但不要宣称已完整展示。
- 普通非首张视觉失败只影响该编号和最终整组验收；不污染首张身份锚点，也不阻塞其他已授权编号。首张失效、未知/未结束请求、损坏返回或尺寸错误仍暂停。
- 发现原QA标准用错时，重新看同一图片和商品要求，用 `review-output` 记录更正理由和旧判定；不重新生图、不修改原图、不抹去失败历史，不增加或重置调用次数。工具只能保存评定，不能证明视觉判断正确。

## 3. 逐张必查表

先并排对照**当前已锁定 outfit/SKU 的全部上传服饰参考图**;不得只拿 look-1 或上一张生成图互相比,也不得混入未选色或另一套 outfit。

| 维度 | 必查项 | 失败处置 |
|---|---|---|
| 服饰硬事实 | 主色/辅色、可见材质观感、廓形/松量、衣长/裤长/裙长、领口/肩线/袖型/袖长/袖口/下摆 | 可见不一致=`qa-retry`;无法从源图判断=`qa-user-review` |
| 结构件 | 纽扣/拉链/门襟、口袋数量与位置、开衩、腰线、绑带、层叠；核对关键事实的部件归属、源图视角及当前应出现的关系 | 新增、删除、移位或改造=`qa-retry`；不能将后中开衩移到前侧、将独立配件材质转移到袖身 |
| 图案与标识 | 图案、logo、字母、标语的位置/大小/方向/是否存在；保留可辨的关键纹样关系，不因概括描述遗漏鸟类或植物等特征 | 明显漂移=`qa-retry`;小字/细纹样不可辨=`qa-user-review`,不得声称准确或猜物种 |
| 原有搭配 | 源图已有鞋、包、腰带、首饰、手表等 | 新增/丢失/换款/换色且用户未授权=`qa-retry` |
| 原人物保真 | 每张是否直接对照原始人物参考保持脸型、表观年龄、肤色与声明身体比例;妆发遵循允许调整项;不露脸是否保持相同轮廓且无可识别脸 | 明显换人或年龄/体型漂移=`qa-retry`;非人像不适用 |
| 候选连续性 | 对照已接受且标明用途的补充图和本组首张，核对可见脸型、年龄感、肤色与声明身体表现；不以生成图之间一致代替原图保真 | 明显漂移=`qa-retry`；无法可靠判断=`qa-user-review`；一致不证明严格锁脸 |
| 真人本轮朝向计划 | 仅real身份沿用核对露脸方向与实际真实覆盖/逐张计划、自然头颈关系和身体动作；AI/new不加该限制 | 超出已定方向或硬扭颈=`qa-retry`；不露脸图只核适用轮廓/动作，面部保真写不适用，不声称锁脸通过 |
| 已声明选角 | 首张是否兑现用户明确的表观年龄、体型表现、妆发和气质;后续沿用原始人物与用户已确认身份,系统建议与未知项分别记录 | 明确可见条件不符=`qa-retry`;年龄/气质难判或主观审美偏好=`qa-user-review`并说明;未指定沿用默认,非人像不适用 |
| 人体与安全 | 手指、四肢、关节、遮挡、年龄得体、非性化、R1–R7;整体头/躯干/腿与人物/家具尺度、支撑重心及前后透视是否自然 | 明显失衡=`qa-retry`;不从未知身体推断实测比例,其余失败=`qa-retry` 或按 safety-core 阻断 |
| 构图与呈现 | 单图单姿势/单构图、对应身体类别编号、本轮实际景别及要求展示的下摆/鞋包、服饰为主角、无拼图/额外文字；全身坐姿按全身检查，半身不强求画外鞋 | 失败=`qa-retry`；不按姿势编号倒推裁切要求 |
| 风格与光影 | 对照选定 pack 的 visual language、场景、四段光影签名及本轮摄影目标，逐条核对实际表现，未改变服饰事实或有效人物条件 | 可定位的已声明目标偏离=`qa-user-review`(附理由);商品、身份、人体/支撑、明确展示要求或重复动作失败仍=`qa-retry`；普通主观偏好列建议 |
| 画布元数据 | 实际宽高是否符合 `canvas_contract`;用户未给像素时是否与首张 `batch_canvas_baseline` 完全一致 | 未读元数据、比例失配、显式像素失配或同组尺寸不一=`qa-retry` |
| 用途规格 | 构图、留白、多景别角色是否符合 `modes-scenes.md §4`;目标画布是否已在 prompt 与元数据门禁兑现 | 未达到目标=`qa-retry`;比例通过也不等于平台审核/投放保证 |

先看整体人体/场景尺度及实际人物条件，再逐项核服饰、风格和文件。画布2:3正确不证明人体比例自然，门襟清楚或氛围改善不能抵消面部漂移；侧望、表情和光线造成的外观变化须分别说明，不用未知原因放行可见失败。修正编辑还对照 `edit-target` 核约定保留的姿态、构图、商品和场景是否被连带改变；底图中待修的脸不能作为通过依据。

摄影对照看明暗主次、色彩、空间层次、身体支撑和视线关系是否按本轮方案兑现，不只数道具是否出现。真人眼球侧望不等于原表情可变，也不证明新增侧脸身份；原表情/妆发条件仍单独核对。摄影改善与商品、面部和人体分别记结果；源码回归、目标段或请求哈希通过不能写成画面已通过，也不能代表其他23个风格的视觉结论。

核对所选slug的 [摄影基准](style-photography-baselines.md) 与本轮已冻结的相容目标，定位具体偏差；编排示例不是自动判废模板，不因改用棚拍、半身或合法的人物朝向而判风格失败。没有实际图片时只记准备检查，不能给摄影通过；风格包或基准文字未修改，也不证明当前画面质量没有回归。

动作1/2的工作区文件必须报告实际文件名和图像尺寸。源 checkout 优先运行:

```bash
python3 scripts/image-spec-check.py --ratio <W:H> [--size <WIDTHxHEIGHT>] --same-size <look-1-or-first.png> <new-or-all-look.png...>
```

若工具不在当前安装包,使用 host 的只读元数据能力做等价校验。只有真正读取到元数据才能写“尺寸/比例已核”;无法读取时保持 `image-draft` + `qa-retry`,不能靠目测放行。即使尺寸符合,也不得保证平台审核、流量、留白像素或发布效果。

## 4. 整组必查

动作1准备交付前必须同时满足:

1. 恰好 6 个独立图片文件,编号 look-1…look-6,文件名唯一,无 preview-grid/contact sheet 混入。
2. 成人真人/不露脸组须有独立 `model_confirmation`,并同时以原始人物参考及已确认 look-1 为身份依据;look-2…look-6 没有明显换人。非人像组跳过身份项。
3. 六张都以上传服饰图为 source truth,没有跨图累积的纽扣、口袋、袖口、logo、首饰、包型或材质漂移。
4. 六张实际元数据都符合唯一 `canvas_contract`;用户未给精确像素时,六张实际尺寸与首张 `batch_canvas_baseline` 完全一致。preview-grid 不得作为基线。
5. 每张目标姿势/非人像构图编号与裁切要求成立;选定 pack、模式、输出形态和用途线索没有丢失。
   真人/不露脸组按本轮实际姿势计划验收:缺背面时第六张应为静止正面站立、双脚落地、无倚靠/迈步/俯身。对照前五张的身体动作、支撑关系与服饰可见方向;只换头部视线、背景、裁切或文件哈希不同不算新姿势。第六张若成了第4张的迈步、或第1张的侧身回转等重复动作,判 `qa-retry`,保留失败图并等待有额度的明确重试授权。交付写“六张独立图,第六张已替代”,不可写“原六姿势/背部结构已验证”。
   真实商品背面有依据、但真人对应回眸无依据时，按已明示计划核第六张背部展示与不露脸，不要求补出回眸脸，也不宣称完整原六姿势或该张面部保真通过。近正脸真人组的动作差异仍按身体与支撑关系验收；AI/new维持原头向流程与既有一致性QA。
   本组明确选定的搭配款式也须逐张对照方案检查；商品源事实始终优先。没有实物/源图支持的搭配细节不能写成已核商品事实。脸部表情连续不要求每张复制相同头部倾斜；头部变化不足可列效果建议，不因要求多样性而违反用户锁定条件。
6. 所有 `qa-retry` 已用用户明确授权的单张重试关闭;所有 `qa-user-review` 已列给用户核对。
7. B7 调用计数已报告;比例失败不得靠静默拉伸/裁切/加边或自动第 7 次调用掩盖。

## 5. `image-ready` 硬门禁

只有同时满足以下条件才能从 `image-draft` 升 `image-ready`:

- 整组结构检查通过,不存在未关闭的 `qa-retry`。
- 六张的实际比例与像素一致性已用元数据证明符合本组 `canvas_contract`/`batch_canvas_baseline`。
- 用户已对照实物/高清源图确认服饰硬事实可接受,并明确接受或关闭所有 `qa-user-review` 项。
- 用户已知发布时的 AI 生成内容标识义务。
- 任何声明的本地文件像素/比例都有实际元数据证据;平台审核、流量、留白像素与发布效果仍不在保证范围。

AI 自评、历史 evidence README、风格测试板或“Open findings=0”都不能代替本轮用户确认。

后续人工/独立复核发现已接受图有明确失败时，第二版任务用 `web-task.py audit-reject --task <task> --look <N> --note <实际失败原因>` 撤销技术接受并保留旧QA、图片、人物确认及累计调用。首张被否决后不再导出或传播该首张；已生成下游是保留证据,不因历史accepted而自动可交付。仅单张且无下游时,明确重试授权可重试,旧人物确认留在历史且新首张必须重新确认。已有下游的首张不可原地替换；需新任务/版本及对应明确授权，不重置总预算。第二版look-2…6不充当身份锚点,迟发否决可在明确单张重试授权后仅修正该张,保留其余已接受图片与首张人物确认;schema1仍按旧行为恢复。首饰、腕表的已确认遗漏不能归为“微小细节待核对”；只有遮挡/资料不足等无法判断时才用qa-user-review。

## 6. 用户可见交付

先展示图片，再用短段落说明人物、商品和用途是否达到目标。只突出影响使用的问题，附实际文件和尺寸；普通单张不另写多份报告。没有阻断项时让用户一次评价当前结果；用户整体接受且范围明确后直接记录并收尾，不另拆人物/服装问句。仅人物接受、硬商品错误和未知请求按 `flow-gates.md` 处理。

下面是按需详细报告示例（内部检查可复用字段，不是默认回复格式）。整组字段只用于动作1，单张省略；不得因用户只要单张而强制补足六张。

```text
商业 QA 状态: image-draft
整组: 应有6 / 实际N / 独立文件N / preview混入=0 / image_gen调用=N
画布契约: 目标比例=<W:H> / 目标像素=<显式值或unset> / 批次基线=<WIDTHxHEIGHT或未建立>

look-1 — qa-pass | qa-retry | qa-user-review
- 服饰硬事实: ...
- 结构/logo/配饰: ...
- 原人物面部保真: ...（直接对照原图；非人像 N/A）
- 候选连续性: ...（与已确认补充图/本组首张对照；不证明原图严格保真）
- 人体/明确选角: ... (非人像写 N/A)
- 构图/风格/光影: ...
- 文件/尺寸: ... / 比例门禁: pass|qa-retry / 批次尺寸门禁: pass|qa-retry
- 处置: ...

整组阻断项: ...
待用户核对项: ...
下一步: 只重试 look-N / 补高清细节图 / 用户确认后升 image-ready
边界: 本地比例/像素只有元数据通过后才可声明;任何情况下不保证平台审核、流量、留白像素或投放效果。
```
