# modes-scenes.md — 三模式 + 自动推荐 + 场景强度框架(模式轴,风格无关)

## 模式与经典姿态

B/C/D只决定棚拍、场景及混合分配；新编号人物任务的动作关系和默认景别来自pose-baselines/current shot_plan。第3经典半身，第5站立自然垂臂微前倾；改为全身/坐姿/支撑须有明确适配范围，不因场景家具自动改变。保留原画布与模式选择门禁。


> **模式轴 ≠ 风格轴。** 本文件只管 B/C/D 三种**生成模式**与场景强度;**具体场景模板与视觉底座来自风格包**(`styles/<slug>.pack.yaml` 的 `scenes` / `visual_language` / `lighting_palette`)。
> 模式可被用户覆盖;风格层默认模式由 `pack.default_mode` 给出。

## 1. 三种生成模式(保留选择能力，按需展开)

默认在简短方案中用“棚拍/场景/混合”说明推荐或已选模式，不要求用户先学代号。用户要比较或查看全部模式时，展示 **A 自动推荐 + B/C/D 三种生成模式**；自然语言改选与代号均保留。A 自动推荐**不是第四种模式**,而是系统在 B/C/D 中选最合适一个的入口。

### B. 棚拍版 Studio Mode
- 特点:可控布光与背景，适合清楚展示细节/轮廓/结构/长度/材质/图案；模式本身不保证生成保真。
- 背景:商品展示默认白/灰或低干扰纯色；穿搭编辑可按方案采用彩色、材质和图形布景；艺术广告可采用明确设计的布景与媒介。棚拍不等于所有风格只能白灰，也不自动添加服装或道具。

### C. 场景版 Editorial Location Mode
- 特点:按视觉用途组织环境与服装关系，适合完整outfit和场景表达；服装保持清楚可辨。摄影默认可信空间，艺术广告允许明确约定的超现实空间。
- 场景强度按下方用途约定；生活穿搭与街拍可作为用户主动选择的表达，不一律改成高端杂志摄影。

### D. 混合版 Hybrid Mode
- 特点:前几张棚拍后几张场景,兼顾保真和商业氛围。
- 默认结构:图1-2 棚拍,图3-6 场景。高风险时:图1-3 棚拍,图4-6 场景。

## 2. 自动推荐逻辑(不剥夺用户选择权)

| 推荐 | 触发条件(=各模式适用品类) |
|---|---|
| **场景版 C** | 完整 outfit / 通勤搭配 / 西装 / 衬衫 / 牛仔裤 / 连衣裙 / 轻商业展示;用户说"更像大片/场景/展示" |
| **棚拍版 B** | 单件上衣 / 单件裙装 / 需验证结构 / logo 文字 / 中式结构 / 复杂图案 / 透明材质 / 超短裙 / 复杂礼服 / 极端前卫 / **电商主图**;用户说"看清细节/先测试保真/电商主图" |
| **混合版 D** | 单件但也想要氛围 / 新品测试后要展示图 / 既要保真又要氛围 / 用户不确定选棚拍还是场景 |

高风险服饰必须提示:**建议先生成 1 张棚拍测试,再扩展 6 张**(处置见 `prompt-build.md §6`)。

## 3. 场景强度框架(风格无关;具体场景由 pack.scenes 提供)

三种表达用途独立于B/C/D：`product-display`商品展示、`styled-editorial`穿搭编辑、`art-campaign`艺术广告。用户明确要求优先，未给用途时按现有交付线索推导；没有线索则沿用已选入口默认，并在简短方案中说明。

- 商品展示：默认low，商品细节、主色和轮廓可辨优先。
- 穿搭编辑：默认medium，环境、光影与造型有清楚关系，尊重所选方向的克制或繁复程度。
- 艺术广告：可使用high、图形布景、超现实空间或插画；具体媒介和变形边界写入visual_plan。艺术化不能成为暗改服装结构或人物身份的理由。

所有用途均避免无关人群、未经要求的第三方品牌和额外文字排版。场景只描述环境，不把“拉伸热身”“快走”“坐在台上”等动作夹带给另一张的shot_plan；室外用实际可解释的天光/遮阴，室内才使用对应窗光来源。可见脚部才要求鞋底接触阴影，不让半身画面强行露脚。

原pack场景与摄影基准作为默认；用户已选模式和具体视觉方案优先。场景高低强度属于表达选择，不是安全风险级别。新方案按[visual-plan.md](visual-plan.md)冻结，旧任务继续读取原有冻结值。

## 4. 用途交付规格 + 批次画布契约

用途规格用于兑现"电商主图/小红书/详情页/品牌大片"等商业预期。它不覆盖风格包 `scenes` / `visual_language`,也不生成带字海报或平台审核承诺。动作1/2 在付费调用前必须先解析一个明确的 `canvas_contract`;**画幅是 core 交付轴,不是 pack 视觉轴**。

### 4.1 `canvas_contract` 解析优先级

1. 用户显式给出的精确比例或像素(`1:1`、`4:5`、`1080x1440`)优先。
2. 用户只给用途/平台时,使用下表的 core 默认比例。
3. 用户既未给比例也未给用途时,独立成片默认 `2:3` 竖版。

同一动作1闭集只允许一个目标比例。用户显式像素必须与目标比例一致;不一致先澄清,不得静默拉伸。动作0 六宫格是非成片预览,使用独立的 grid 画布,**不能**成为动作1批次尺寸基线。

| 用途线索 | 默认 `canvas_contract` | 构图规格 | 注意 |
|---|---|---|---|
| 电商主图 / 高转化 / 淘宝白底 / 商品主图人像 | `1:1` | 主体居中,服饰完整,低干扰背景,适度留白,true-to-product color | 优先 B 或 ecommerce-studio;不做夸张大片遮挡 |
| 小红书 / 社媒封面 | `3:4` 竖版;用户明确 `4:5` 时覆盖 | 服饰主体清楚,上方/侧边留白可放封面字 | 不自动生成封面文字;如需带字转 xhs/ecommerce 内容系统 |
| 详情页人像 / 商品详情 | `4:5` 竖版 | 可建议全身/背面/面料/logo/鞋包细节组合;未明确前仍用默认闭集 | 用户明确要细节时替换对应编号位,总数仍保持 6 张闭集;少于 6 个 shot 用默认闭集补齐,多于 6 个先请用户取舍;不并发 |
| 品牌大片 / 投放素材 | `2:3` 竖版 | 视觉中心明确,低干扰 negative space,保留风格氛围和服饰主角 | 不自动做海报排版/contact sheet/文字 layout |
| 无用途线索 | `2:3` 竖版 | 服饰人像/商品呈现的通用安全边距 | 用户可在风格动作中一句话覆盖 |

### 4.2 执行与声明边界

- 每条动作1/2独立图 prompt 都注入同一个精确目标比例、方向和安全边距;不得只写"竖版倾向/方形倾向"。
- 原生生图 host 可能忽略 prompt 并返回内容自适应尺寸,所以**提示词不等于合规证据**。每张落盘后必须按 `prompt-build.md §4.0b` 读取元数据。
- 用户给了精确像素时,每张必须匹配该像素;用户只给比例时,首张通过比例门禁后的实际像素成为本组 `batch_canvas_baseline`,后续五张必须同时匹配目标比例与该像素尺寸。
- 统一任务记录：新 schema2 任务在 `context.canvas_policy` 写 `ratio-first`（用户未给精确像素）或 `exact`（明确像素）；`size` 与 `context.size` 一致，前者策略下只表达目标比例的正整数宽高，不向用户暗加精确像素要求。首张有效原图及其重试历史提供不可重置的像素基线，后续导出使用该实际尺寸。旧任务没有此字段时仍按 `exact` 恢复，不静默放宽。
- 未实际读元数据不得声称比例/像素合规;读到并通过后只可声明“本地文件符合本组画布契约”,仍不得保证平台审核、流量、留白像素或发布效果。
- 禁止为掩盖失败而静默拉伸、强裁切、加边或从 preview-grid 放大。需要后处理或重生时保留原图、版本化输出,并重新执行服饰/构图 QA;涉及新的原生生图仍需用户明确授权。
